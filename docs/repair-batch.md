# 修复候选批量验证与证据排序

更新日期：2026-10-26。P3 第二阶段在既有单候选流程上增加 Core、CLI、Qt 批量验证、全部候选记录和确定性排序。每个候选独立作用于一份原始源码副本；不把多个候选合成补丁，不自动应用原始工程。模板及单候选门槛沿用 [修复候选说明](repair-candidates.md)。本轮验收索引见 [批量验证证据](evidence/repair-batch-20261026.json)。

## 使用

后续已增加可选 gcov 采集、所选行执行记录门槛及 `evidence-lexicographic-v2`，见 [覆盖率说明](repair-coverage.md)。下文 v1 是本阶段原始排序记录；默认关闭采集时继续按原证据顺序工作，覆盖率不被假定为已测量。

Qt 的修复对话框增加“验证全部并排序”。它验证当前问题已生成的所有候选，显示排序表；单击某一行切换到对应差异和验证详情。每行保留状态、测试总数/失败/跳过、修改字节及未评估的正确性。重新生成候选会清除旧结果；单独重验会隐藏旧批次表，避免把不同时次的结果混合显示。后台运行、取消及安全关闭继续有效。

CLI 可以汇总同一工程、同一扫描和配置的多个已导出候选，也可来自该扫描的不同问题：

```powershell
codeguard-cli repair evaluate D:\demo --database D:\results\scan.sqlite3 `
  --output D:\results\batches `
  --candidate D:\results\candidates\A\candidate.cgfix `
  --candidate D:\results\candidates\B\candidate.cgfix `
  --cxx-compiler D:\toolchain\bin\g++.exe --jobs 2 --timeout 60
```

`--candidate` 仅在 `evaluate` 中可重复；单候选 `validate` 的重复参数仍会被拒绝。批量参数为 1—64 个不同内容 ID，原始/修改后源码载荷合计不超过 64 MiB。完整校验输入后才导出或执行；重复 ID、不同工程/扫描/配置、非法候选及源码树内输出会拒绝启动。

批次正常结束且至少一个候选通过门槛时 CLI 返回 0，没有通过者或原始源码改变时返回 2，整批取消返回 130。返回 0 只表示存在通过者，不能解释为全部候选或全部工程问题都已修复。JSON 单独提供 `gates_passed_count`、`any_gates_passed`、`all_gates_passed` 和 `attempted`。

## 排序的含义

排序为固定的逐项比较规则 `evidence-lexicographic-v1`，依次比较：

1. 全部门槛通过、已评估但未通过、已取消、未运行。
2. 有实际执行且完整通过的测试；其次是否有无跳过的已执行测试。
3. 编译通过。
4. 同配置原始对照完整、目标问题复现且候选分析完整。
5. 目标规则不再检出。
6. 新增/重新显现告警更少；未知计数排在已知计数之后。
7. 修改字节更少，再以内容 ID、输入顺序稳定打破平局。

修改字节表示插删的字节数：纯插入/删除按新增/移除量计算；其他修改先剔除共同前后缀再统计替换量。当前三种模板均为纯插入，因此比较运算符增加一个字节、意图括号增加两个字节。UTF-8 按字节计数，此数不是代码行数或语义影响大小。

排序不产生正确性分数或自动选择。没有测量行/分支覆盖率，统一输出 `test_coverage: not_measured`；`correctness` 始终为 `not_assessed`。测试数量不是覆盖率。若测试不足以区分行为，保留错误行为的意图候选也可能通过门槛，仍需人工审阅。

## 记录、失败与取消

每次调用创建新的 `batch-*` 目录。开始执行前导出全部候选，写入 `progress-0000.json`；每次尝试后追加不可变的 `progress-NNNN.json`；最终写 `batch.json`。最终 JSON 按验证排序展示，保留从零开始的 `input_index` 和原始候选 ID。每个导出目录的 `batch-validation.json` 保存其本批次最终结果，实际运行目录保留单候选 `validation.json`、分析数据库和构建日志。

失败不会中止其他独立候选。候选开始前发现源码不匹配等异常也保存失败记录。若验证发现原始 C/C++ 清单或内容在运行中改变，整批停止，剩余项保留 `not_run` 和原因。

整批使用独立取消控制，每个候选另有自己的提交屏障。第一项完成不会封死后续取消。取消正在运行的项时保留已完成项、当前项和所有未运行项；开始前立即取消也生成未运行记录。安全关闭等待记录收尾。新的尝试创建新目录，不自动删除历史批次。

进度文件用于观察和诊断，目前不支持从检查点自动恢复。若进程被强制终止，最终文件可能尚未生成，应查看最后一份完整进度文件。磁盘不可写、导出阶段异常等错误不能保证最终记录写入，错误会向调用者返回。
