# P3 第八阶段：重复路径解析与大工程验证成本

更新日期：2026-10-27。沿用第七阶段固定的 libgit2 父/子提交、Windows 静态库配置及四项公共 API 回归。性能检查与正确性门槛分别留档；完整结果见 [本轮机器可读证据](evidence/repair-validation-performance-20261027.json)。

## 优化范围

原文件清单扫描和源码副本复制，对每个目录项、每条相对排除路径分别调用两次 `weakly_canonical`。本基准有 42 条排除路径、772 个目录项；大量重复文件系统查询发生在 AST 分析之外。只读完整快照另测约 1.24 秒、峰值工作集约 347 MiB，不能据此把快照读取当作上一轮总耗时的主要原因。

现在每次遍历创建独立的排除过滤器：排除路径各解析一次，目录项最多解析一次，然后逐组件比较，保持大小写、路径边界、精确文件排除和默认忽略目录语义。没有全局长期缓存，也没有缓存文件内容、减少扫描文件、跳过原版或补丁 AST。源码副本仍保留复制前后完整清单和内容核对，修复后仍进行完整配置对照及原版/修改版静态分析。

遍历结束时重新检查排除路径解析结果。Windows 还比较最近可访问祖先或目标的卷号/文件标识，拒绝目录被替换、原来缺失的排除祖先出现或目录联接重定向后产生的成功结果。文件时间戳不参与这项身份判断。错误和取消仍向上传递，不保存成功快照或继续成功构建。

## 测量方法与边界

`codeguard-input-probe` 只读已有数据库和源码。inventory 模式只执行文件清单扫描，snapshot 模式读完整快照；它不代表 AST 分析或完整修复耗时。冻结的旧探针与当前探针串行运行，逐文件比较路径、内容摘要、字节数和物理行数，并记录可执行文件 SHA-256、进程时间和 Windows 工作集。首轮旧探针与编译重叠，另保留无编译/测试负载的串行复测，不把首轮当作严格隔离结果。

两版必须均为 599 个文件、271818 个物理行，且所有四项逐文件字段完全一致；完整快照中的文件记录也参与核对。具体每轮时间及峰值内存以证据中的原始记录为准，文件清单阶段的倍数不能外推为整套分析或任意项目的提速。

| 读取方式 | 耗时/秒 | 负载说明 |
|---|---:|---|

这次本机旧/新版文件清单复测相差约 152 倍；这是特定 Windows 工具链、路径和 42 条排除项下的观察。完整快照读取仍有约 338 MiB 峰值工作集，本轮未优化这项内存成本。

本轮还重新执行原生缺陷版/参考版测试，以及生成修复组合和意图负对照的完整副本构建、测试、原版和修改版静态复查。复用第七阶段已完成的扫描和提案会单独记录；不把提案重放说成重新生成。分析器/规则和 C/C++ 输入未修改，244 个有效 TU 的范围保持不变，正确性字段仍为 `not_assessed`。

初始测量探针直接以未规范化的项目根查询配置，因找不到配置退出；改用公开 `load_project_config` 接口后重新测量，失败记录不计入性能对比。目录联接检查的初始断言假设工具链会展开目标，实测与原公共路径判断不符；最终保留原范围语义并增加原生身份变化检查。两个开发期失败及后续复测均保留，没有用后续成功覆盖原记录。

## 路径与并发边界

逐组件比较防止 `skip` 错误排除 `skip-neighbor`，Windows 大小写比较沿用原实现。当前 MinGW 的 `weakly_canonical` 对本机目录联接没有展开目标；过滤器保留原公共路径判断的范围语义，不能据此声称已统一所有 Windows 别名或修复全部联接遍历问题。额外的原生文件标识检查用于发现排除别名变化，测试在没有符号链接权限时用临时目录联接实际验证，没有更改权限或系统设置。

开始/结束检查不是原子文件系统快照，无法保证检测到期间短暂改变后又恢复的所有状态。现有源文件哈希/大小/时间与副本核对继续保留；未锁定外部依赖和构建工具。测试、告警消失和参考结构匹配仍不能证明通用修复正确率。

本轮审计另发现既有 Git 归属问题：从归档提取的源码目录没有 `.git`，构建日志中的 Git 命令向上发现了 CodeGuard 父仓库，记录了宿主提交 `68a3490508deece1bfa6c2bc29a375d69ddbb00e`。该记录不能作为 libgit2 的版本证据。此处源码来源始终按固定归档 SHA-256、ZIP 注释提交号和准备后逐文件 SHA-256 独立核实，未以该 Git 字段判定修复正确性。原日志保留，父仓库自动发现的修正列为下一项工作，不能称本轮已修复。
