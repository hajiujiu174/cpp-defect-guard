## 界面与操作

新增“查询”页：输入 SELECT 查询当前已保存快照，支持 `files/functions/symbols/edges`、过滤、多字段排序及 LIMIT。执行计划按需展开；错误包含行/字节列位置，并清空旧结果；双击含 file/line 的结果可定位源码。新快照载入后旧查询结果清空。此页使用自己的查询条件，隐藏其他标签页的文本筛选框。详细语法及 2000 行显示边界见 [查询语言](query-language.md)。

- 顶部：导入工程并扫描、重新扫描、打开已有分析数据库；可选 `compile_commands.json`。
- 任务栏：阶段、当前文件、已处理数、进度条与取消按钮；显示运行中、正在取消、正在提交、已完成、部分完成或失败。
- 左侧：扫描清单组成的工程文件树，仅展示实际接入的 C/C++ 文件，排除目录不会重新出现在树中。
- 中间：只读源码、行号、基础 C++ 词法高亮、当前行高亮、文件路径与状态栏。
- 右侧：文件、符号、复杂度、关系边、循环分量、解析诊断；输入框筛选当前标签页。
- 点击文件树、文件行、符号行、复杂度行或关系边，跳到对应源码位置；诊断按所属文件打开首行，不伪造精确错误行。
- 打开已有数据库，恢复其中最近工程，不重新扫描；“重新扫描”显式更新快照。新扫描仍追加批次，保留历史。

启动：

```powershell
cd D:\Work\WORKDONE\cpp-defect-guard
.\scripts\run_codeguard.ps1 -Analysis -Gui
```

不带 `-Analysis` 的 `-Gui` 使用轻量模式，文件浏览可用，Clang 编译数据库控件禁用。带 `-Project <目录>` 可启动后自动导入；带 `-Database <文件>` 可免去数据库选择对话框。所有数据库仍必须位于源码目录之外。

## 源码保护与范围

源码通过只读文件句柄打开；只允许浏览当前扫描清单里的文件，解析后的真实路径也必须位于工程目录内。拒绝 `../` 越界、清单外文件、已删除文件及超过 2 MiB 的文件。

源码按 UTF-8 显示。查看时重新比较内容 Hash：若与保存快照不同，明确提示重新扫描，旧位置仅供参考；原始文件不会被改写。源码没有编辑、保存、补丁应用或自动修复按钮。高亮是轻量词法显示，不是完整 C++ 编辑器，raw string 等复杂语法的着色不作正确性保证。

调用/依赖仍采用边表与循环 SCC 列表，不是可拖拽图画布。“问题”页现已接入五类 AST 规则，支持筛选、证据/建议和点击定位；无告警不代表无缺陷。新增“构建测试”与 Git 页，后台副本构建、历史、日志和取消详见 [Level 3](level3-acceptance.md)。

## 后台扫描、进度与取消

`gui/qt/scan_task.*` 使用一个独立后台任务协调文件扫描、多 TU Clang 分析池、源码一致性复查与单写线程；GUI 每 25 ms 读取合并后的最新进度，不为每个符号排队发送事件。结果与异常在 GUI 线程处理，SQLite 连接只在所属写线程使用。Clang 使用任务独立的物理文件系统，避免改变进程工作目录干扰源码浏览。

- 扫描时文件树、只读源码、结果标签页和筛选仍可操作，继续展示上次已提交结果；导入、重新扫描、打开数据库和编译配置暂时禁用。按钮禁用之外，业务入口也拒绝重复启动；一个窗口只允许一个扫描任务。
- 文件发现阶段显示实际已处理数和不定进度；Clang 阶段显示已完成/总翻译单元。百分比属于当前阶段，不是预测耗时或整体百分比；保存、准备等阶段使用不定进度。
- 点击取消进入“正在取消”，暂不允许新任务。文件读取每 64 KiB、目录遍历、翻译单元边界和数据库各条记录写入间检查取消；SQLite 锁等待也每约 10 ms 检查标志。单个正在执行的 Clang TU 不强制中断；其结束后才响应取消，阻塞 I/O 仍可能延迟响应。
- 取消成功后进入“已取消”，进度归零、按钮恢复；旧快照、源码位置、表格和筛选条件不变，可以再次扫描。失败同样不替换旧视图；Clang 部分失败但成功保存的分析明确显示“部分完成”，不是取消或全量成功。
- 取消与提交通过原子状态切换确定先后：取消先到则回滚本次事务；提交边界先到则拒绝取消，并等待真实提交结果，不会出现“已取消但保存了新快照”。在这之前，扫描仅在内存构造结果，数据库以只读方式取得历史。
- 所有项目、批次、文件、符号、度量、边及覆盖记录在同一数据事务内保存。取消不追加半成品扫描，也不替换旧历史。首次扫描若已经初始化数据库，取消可能留下**只有表结构、没有项目/扫描数据**的数据库；旧版数据库的结构升级也可能保留。这是快照一致性保证，不是数据库文件字节完全不变。
- 扫描期间关闭窗口，先请求取消并延迟关闭，任务安全结束后退出；越过提交边界时等待提交结果。没有强杀线程，也没有遗留后台任务继续写库。

当前由单个后台控制器协调 Core 多 TU 线程池；窗口内扫描与构建任务互斥。已补充 2,048 文件清单和 128 TU / 4,096 函数的合成规模测试，以及完整窗口结果填充计时，见 [规模与锁竞争验收](qt-scale-acceptance.md)。真实大工程、同步打开大型历史数据库与长时交互尚未全面验收；不宣称任意规模下零卡顿。

- `codeguard.qt_background`：确定性停在事务内，用 Qt 事件循环处理输入和计时器；验证工作线程/GUI 回调线程、重复启动拒绝、取消回滚、旧视图保留、取消后重扫、异常后旧结果保留；启用 Clang 时还验证部分完成状态与数据库一致。
