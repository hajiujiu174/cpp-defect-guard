# 原版与补丁的多轮覆盖对照

更新：2026-10-27。P3 第六阶段，Windows 本机实现。修复正确性始终为 `not_assessed`；覆盖对照提供审阅证据，不提供因果或正确性证明。

## 使用

先扫描并导出当前快照的单个 `candidate.cgfix`，或显式组合 2—16 项为 `repair.cgset`。然后运行：

```powershell
codeguard-cli repair compare D:/project --database D:/records/scan.db `
  --output D:/records/comparisons --set D:/records/repair.cgset --runs 2 `
  --cxx-compiler D:/tools/g++.exe --gcov-tool D:/tools/gcov.exe `
  --coverage-test-limit 64
```

单候选用 `--candidate FILE` 替换 `--set FILE`。每个版本支持 2—5 轮，默认 2；该独立操作总是采集整套和逐测试组 gcov 数据，不改变普通 `validate` / `evaluate` 默认关闭覆盖率的行为。需要 GNU GCC、匹配的 gcov、CMake/Ninja 和 CTest 3.29+；Windows 输出绝对路径须只含 ASCII。运行包不附带这些开发工具。

Qt 的单候选及组合窗口均有独立“多轮覆盖对照”按钮及轮数。使用当前构建设置、gcov 路径和测试数上限；需要时先勾选覆盖率来编辑工具路径。多轮按钮本身会启用整套及分组采集，不依赖两个采集复选框的选中状态。后台执行，取消和安全关闭保留全部预分配轮次状态。界面仅展示有上限的摘要，完整结果见输出目录中的 `comparison.json`。

`samples/repair-comparison-demo` 含两个故意保留的 CG003 问题、五个声明测试和自动 fixture。两项比较修改组合后通过测试；未修改的 `helpers.cpp` 展示执行记录变化。可通过 `scripts/accept_repair_comparison.py` 用实际 CLI 复现。

## 对照过程与输入边界

- 第 1 轮先原版后补丁，第 2 轮先补丁后原版，依次交替。每次观察使用全新源码副本及独立构建，避免复用前一观察的计数或构建产物。每个补丁观察继续执行已有的同配置原始静态对照、全部目标消失、无新增/显现告警、CTest 和完整 C/C++ 副本校验。
- 在任何 CMake 配置前，冻结首次实际复制的全部文件和目录清单，包括构建脚本和资源。后续配置前后核对完整副本，补丁版仅允许已提议的精确字节修改。拒绝软链接、越界、不支持的文件类型及超限输入。内容指纹仅用于一致性核对，不是密码签名。
- 每次观察后及最终核对原始 C/C++ 清单和首次实际复制的已知原始输入；已知资源变化时停止后续观察。没有锁定外部依赖、操作系统环境、网络、工具权限、未复制文件或后来新增的未知资源；没有阻止同权限构建程序访问原始目录。这是内容核对流程，不是操作系统隔离环境。
- 测试目录只忽略调用回溯及临时源码/构建根路径，保留测试名、命令、顺序内参数和属性。根路径按 JSON 编码与分隔边界归一化，排序测试名；完整归一化文本一致才认定目录匹配。保留的 `$SOURCE` / `$BUILD` 标记不能出现在原目录数据中。gcov/CTest 版本必须一致且非空。
- 每个观察先运行整套测试，再按声明测试及传递依赖/自动 fixture 逐组重跑。每组重置计数，但组内环境和构建仍共享；测试组不能归因于请求的单个测试。所有完整组（含正常返回失败的原版组）的行执行并集须与整套一致。

原版正常返回非零的测试仍记为失败，分组和整套结果加诊断标记。失败组还须有普通 `Failed` JUnit 记录，且项目 `.gcda` 数量与 `.gcno` 数量一致且非零；否则保留诊断记录，但不具备完整比较资格。多可执行文件工程中某些目标未运行，也可能触发这一保守拒绝。

禁用、跳过、未运行、CTest 已识别的异常/超时或计数文件不齐全的观察不参与完整比较。Windows 的 `abort()` 可能只被 CTest 标成普通 `Failed`，本轮反例由计数缺失检查拒绝。计数文件齐全仍不能证明每个子进程都完整刷新计数，例如同组 fixture 已产生计数后另一进程提前退出；本流程无法识别所有中断或外部行为。原版失败也可能改变后续测试路径，需人工解释差异。

## 行对应与状态

只按提议的原始字节范围建立整行对应；未触及且字节完全相同的行可比较。保留 BOM、CRLF、重复文本及末行无换行的坐标关系，不通过文本相似度猜测对应。被修改、合并、拆分或无法配对的行单列，另一侧行号为 0，`transition=not_comparable`。

| 状态 | 含义 |
| --- | --- |
| `newly_recorded` / `no_longer_recorded` | 未修改对应行在各自版本所有轮次中一致地由无记录变为有记录，或相反 |
| `instrumentation_added` / `instrumentation_removed` | 插桩行范围发生变化，不当作执行增减 |
| `observed_variation` | 同一版本轮间执行或插桩记录变化 |
| `unknown` | 缺少完整轮次，无法给出稳定比较 |
| `not_comparable` | 修改或无法配对的行 |

比较使用行是否有执行记录，不比较原始命中次数、分支数量、时间或正确性概率。同一物理行上多个表达式不能分别归因。未插桩文件不进入分母；未插桩也不能当作未执行。

`ready_for_review` 要求所有观察完整、输入/目录/工具一致、同版轮间覆盖及测试结果稳定、分组并集与整套一致，以及所有补丁标准验证通过、原始内容核对通过。该状态表示记录可供审阅。Core 无 Clang 时仍可采集并比较，但静态门槛无法通过，不能变为该状态。CLI 此状态返回 0，取消返回 130，其余已留档结果返回 2。

## 留档与资源限制

输出保留候选或组合清单、差异、原始/补丁输入清单、所有观察、独立构建/测试日志、JUnit、原始 gcov 数据、标准补丁验证、归一化测试目录及汇总 JSON。预分配全部轮次；取消/失败后未运行项仍在报告中。过程不自动将补丁应用到原始项目，不提交或推送代码。

单个待修改文件不超过 2 MiB；复制输入最多 100000 项、2 GiB；声明测试数默认上限 64，允许 1—256；最多累计 1000000 条观察行记录、200000 条比较行；观察后检查总留档 2 GiB 预算。预算是受控失败上限，不是实时磁盘硬配额；最后一次观察可能暂时超过预算。每次构建/测试沿用进程超时设置，取消随现有进程控制生效。

## 本轮验证

最终本机 Core 完整回归 78 项：77 通过、1 符号链接权限跳过。Clang/Qt 的修复、覆盖对照、构建/进程及关联界面共 96 项全部通过，包含新增 12 项实际对照/GUI 检查和 12 项行映射/目录归一化检查。本轮没有重新运行整个 Clang/Qt 套件或三个真实库，不能沿用历史全量与真实库计数声称已重测。

首项进程检查曾因把 JUnit `fail` 算为未运行而失败，已区分“执行失败”和“未执行”；中间 12 项中 Windows abort 反例曾被错误认定为完整，补强失败组计数文件检查后，最终 96 项中的该反例通过。两次原始失败与最后复测记录均保留，没有删除失败后声称首次全绿。

最终运行包的 CLI 五测试组合样例、两版各两轮、fixture 组、未修改辅助行增减、原始全部输入 SHA-256 一致性及 Core 无 Clang 边界通过。隔离 PATH 下的 CLI/Clang、中文字体、关系图、Qt 修复预览/导出/取消留档通过；两个新对照窗口的真实控件测试和最新截图已检查。包内 CLI、GUI、SDK 与最终构建逐项 SHA-256 匹配。
