# 真实上游修复与错误返回值对照

更新：2026-10-27。P3 第七阶段已完成下述 Windows 本机验证。该阶段以真实提交和实际公共 API 行为为依据，产品仍保留 `correctness=not_assessed`。

## 固定来源

选择 libgit2 已合并的 [PR #7426](https://github.com/libgit2/libgit2/pull/7426)，修复提交 [`dca35e94`](https://github.com/libgit2/libgit2/commit/dca35e94a61b79e77e381ea59b0d9142163e87a5)，父提交 `f28579db11737eaa2ced18498e229967a12f1c3f`。当前读取的上游主分支历史包含该修复，没有以未合并提案充当参考答案。

原代码在 `diff_generate.c` 和 `merge.c` 的四处条件中将 `error = function() < 0` 写成赋值表达式，先得到比较结果 0/1，丢失了真实错误码；参考修改将赋值括起来，再执行 `< 0`。来源、完整差异、位置和覆盖边界保留在 `benchmarks/libgit2-error-return`。

## 检测和候选

CG003 现在检查 if / while / do / for 条件的逻辑与、逻辑或子表达式。对非 bool、非 volatile 的局部整数变量，若赋值右侧是未单独括起来的整数比较，会提示核对优先级。已经明确括起右侧比较的布尔赋值保留原有意图规则；未知别名、重载和不兼容宏范围不猜测。

新增 `condition.assignment_result`：在原始赋值值表达式之后再比较，例如 `error = call() < 0` → `(error = call()) < 0`。编辑使用 Clang 字节范围，保留源文本；单候选、批量、组合及覆盖对照共用现有流程。Core 编解码和位置映射、CLI 导出/验证、Qt 单候选/组合标签与风险说明均已接入。

该候选会改变保存值，可能影响类型转换与求值顺序，必须审阅意图。给局部整数赋布尔值也可能是有意行为，新增 CG003 提示不能直接当作已确认缺陷。显式意图候选保留原行为；在仍有通用条件赋值提示的语法中，它可能继续被静态门槛拒绝。所有备选都经过既有门槛，不因模板名称自动认定正确。

只插入括号的变更另作字节映射，避免同一调用原有 CG001 提醒被误算为新增。重复括号无法唯一对应的字节保留未知。C/C++、逻辑组合及循环、组合修复、内层已有告警和 Qt 真实控件已有专项检查。

## 原始、参考、候选及负对照

基准的 C 回归程序由本项目编写，直接链接未改写的上游库源码，使用真实公共 API。它不运行上游原有完整测试集，不能把四个自编检查算作上游测试通过。

| 场景 | 缺陷版已观察结果 | 上游修复版已观察结果 |
| --- | --- | --- |
| `git_diff_tree_to_workdir` 非法选项版本 | 返回 `1`，检查失败 | 返回负值，检查通过 |
| `git_diff_index_to_index` 非法选项版本 | 返回 `1`，检查失败 | 返回负值，检查通过 |
| `git_merge` 读取损坏索引 | 返回 `1`，检查失败 | 返回负值，检查通过 |
| 合法空索引 diff 对照 | 通过 | 通过 |

四处参考修改涉及三个函数；尚未独立触发 `git_merge` 第一次 `git_repository_index` 调用的失败，不将这一位置计入行为已复现数量。

生成的四项 `condition.assignment_result` 组合通过全部四项回归，三个错误场景均返回 `-1`；原始对照和修改后各 244 个 C/C++ TU 全部解析，四个目标未再检出，告警由 23 减至 19，新增/显现告警为 0。全部 C/C++ 副本内容和原始输入核对通过。四项意图候选组合也消除了四个提示，但三个错误场景仍返回 `1`、三项测试失败，验证门槛正确拒绝该负对照。

参考比较使用当前编译参数重新导出的 Clang AST，对三个相关函数保留类型、运算符、转换、声明名称和子树结构。原始、上游修复、生成补丁、意图负对照分别比较；不是删除文本括号后比较字符串。该比较器只用于这个已固定修复与配置，不能证明所有配置、外部行为或任意程序语义等价。
