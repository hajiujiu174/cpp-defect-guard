# Qt 后台扫描：规模与锁竞争验收

## 本轮范围

延续后台扫描、进度与取消，补充可复现的规模测试和数据库被占用时的取消测试。没有接入线程池、新规则或模型训练，也没有改动用户工程源码。这里的语料是测试代码生成的合成 C++ 工程，不能替代真实开源工程或完整课程交付验收。

每个生成的翻译单元含 32 个带条件分支的独立函数；使用真实 Clang 编译参数、解析和 SQLite 持久化。临时源码和数据库位于构建测试目录下的专用随机目录，测试对象销毁时清理；分析前后比较源码清单和内容 Hash。

## 发现并修正的问题

另一连接持有数据库写锁时，原实现虽然不阻塞 Qt 事件循环，但点击取消后仍要等待 SQLite 的 5 秒忙等待超时。实测取消至任务结束为 **4,961 ms**，旧快照未损坏，但取消体验不合格。

现由连接内部的 SQLite busy handler 每约 10 ms 检查任务取消标志，无取消时仍保留约 5 秒的锁等待上限。扫描的读历史、数据库初始化/迁移及写入连接均携带当前任务标志；直接调用 `save` 也可传入本次取消标志，并在离开时恢复连接原标志。回调只读原子状态，不跨线程操作 SQLite 连接，不涉及 Qt。

取消导致的数据库忙错误在 `import_project` 边界统一转换为 `ScanCancelled`。数据事务已开始则回滚；事务尚未开始则不伪造回滚成功。提交状态仍使用原子边界：越过边界后拒绝取消，即使提交正在等待读锁也不能标成“已取消”。

## 本机观测结果

Windows，现有 Clang 22.1.8 / Qt 6 / SQLite 构建；Qt offscreen，10 ms 心跳。下表来自本轮一次完整测试运行，耗时不是跨机器承诺；其他构建任务、文件缓存和系统调度会影响结果。

| 场景 | 规模 | 扫描/分析耗时 | 取消响应 | 后台最大心跳间隔 |
|---|---|---:|---:|---:|
| 文件清单任务 | 2,048 文件，不解析 AST | 1,330 ms | 27 ms | 12 ms |
| Clang 后台任务 | 128 TU、4,096 函数 | 24,050 ms | 186 ms | 13 ms |
| 数据库写锁占用 | 已有快照，另一连接持有 IMMEDIATE 事务 | — | 28 ms | 12 ms |
| 数据库读访问受阻 | 另一连接持有 EXCLUSIVE 事务 | — | 30 ms | 11 ms |
| 完整主窗口 | 128 TU、4,096 函数 | 22,749 ms | 在事务提交前验证取消 | 13 ms |

完整窗口的第二次扫描至取消结束用时 20,707 ms，其中包含再次执行全量 Clang 分析；**它不是取消延迟**。扫描结束后同步填充全部结果控件耗时 119 ms，测试中的再次载入为 109 ms。这表明当前规模没有出现秒级结果填充停顿，但仍有约 0.1 秒的主线程同步工作，不宣称零卡顿。

控制器规模测试没有人为延缓扫描：工作期间 Qt 持续处理计时器、输入和重复启动尝试，再由 GUI 发起取消。完整窗口沿用提交前的确定性测试闸门，检验真实筛选/标签/取消控件、状态恢复、旧源码/位置/筛选/数据库快照保留及安全关闭。两种验收目的不同，不把闸门等待计入自然取消延迟。

## 自动测试与复现

新测试：

- `codeguard.qt_lock_cancel`：持有写锁，开始等待后再取消，要求取消至结束小于 500 ms。
- `codeguard.qt_read_lock_cancel`：独占锁阻塞读历史，验证取消与快照保留。
- `codeguard.qt_scale_inventory`：2,048 文件，完成一次扫描后取消重扫。
- `codeguard.qt_scale_clang`：128 TU、4,096 个函数的实际 Clang 分析和边界取消。
- `codeguard.qt_scale_window`：在同规模工程上启动完整 GUI，验证结果展示、取消和延迟关闭。

控制器规模测试还要求后台阶段最大 Qt 心跳间隔小于 500 ms，避免“扫描完才处理少量输入”也被判为通过。该阈值是本机回归门槛，不是产品实时性保证；受限 CI 可单独运行 `scale` 标签并保留原始观测。

```powershell
cd D:\Work\WORKDONE\cpp-defect-guard
cmake --build --preset analysis-release -j 4
ctest --preset analysis-release -L scale -V
# 快速功能回归，不包含规模测试
ctest --preset analysis-release -LE scale --output-on-failure
```

规模测试输出 JSON 计时记录；完整窗口输出 `GUI_BACKGROUND_TIMING`、`GUI_DISPLAY_MS` 和 `GUI_SMOKE_OK`。原始 CTest 输出位于 `build/codeguard-analysis/Testing/Temporary/LastTest.log`，下次测试会更新它。

本轮完整回归：分析版 38 项通过、1 项符号链接权限跳过；轻量桌面版 26 项通过、1 项跳过；纯 Core 21 项通过、1 项跳过。旧 Python/模型测试未重跑。

读锁、写锁取消用例另各连续执行 10 次，均满足 500 ms 取消门槛；新增心跳门槛后，分析版和轻量版相关规模用例再次通过。

## 仍保留的边界

- 单个 Clang 翻译单元内部仍不强制中断；复杂模板或阻塞文件 I/O 可能增加取消延迟。
- 首次初始化或旧数据库结构升级可能保留表结构，但取消不会提交半成品扫描记录。
- 本轮没有真实桌面人工点击、百万符号、大型第三方工程、长时间稳定性或多线程吞吐验收；结果表格仍同步填充。
- 后续优先补真实工程基准，再据数据决定虚拟化表格、异步历史载入或并行解析，不能用合成语料直接宣称生产级规模支持。
