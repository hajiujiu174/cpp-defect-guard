# 引用索引、查找引用与函数度量

更新日期：2026-09-23。P2-2 第一阶段：引用与度量。局部空值传播、数组区间分析、交互图画布和路径查看仍在后续计划中，未计为完成。

## 使用

重新执行带 Clang 编译数据库的扫描后，CLI 用 `symbols` 找到目标 USR，再精确查找引用；重载和同名局部变量使用不同 USR。

```powershell
& $cli symbols $project --database $db --prefix alpha
& $cli references $project --database $db --symbol 'c:@F@alpha#I#'
& $cli query $project --database $db --query "SELECT file, line, column, kind, translation_unit FROM references WHERE symbol_id = 'c:@F@alpha#I#' ORDER BY file, line;"
& $cli query $project --database $db --query 'SELECT name, max_nesting, fan_in, fan_out FROM functions ORDER BY max_nesting DESC;'
```

USR 示例只适用于对应样例的 `alpha(int)`，其他工程须使用实际符号 ID。`references` 输出分析状态、引用观测数及制表符表格；未知 USR 报错。部分覆盖仍返回已有引用，同时保留 `partial` 和退出码 2。没有引用记录不能证明未被使用。

Qt 在“符号”或“度量”表选中行，右键“查找此符号的引用”。结果复用后台查询、取消及旧快照结果保护。双击引用结果定位文件、行和 UTF-8 字节列；右键查询结果可跳到目标符号的定义，只有声明时跳到声明。源码仍限工程清单内、2 MiB 以内；源码已改变会提示旧位置仅供参考。外部库的源码位置保留在记录中，但不会绕过工程范围直接打开。

## 引用语义

`SymbolReference` / 查询表 `references` 保存：`symbol_id`（目标）、`enclosing_symbol`（所在函数，无法确认时为空）、`kind`、`file`、`line`、`column`、`translation_unit`。

| kind | 来源 | 边界 |
|---|---|---|
| declref | 已解析的 DeclRefExpr | 函数、变量、参数、枚举常量等名称使用，包括函数取址 |
| member | 已解析的 MemberExpr | 字段、方法等成员使用；不推断运行时虚分派 |
| construct | 显式可标识构造目标 | 隐式、没有稳定 USR 的构造目标不编造记录 |
| type | TagTypeLoc / TypedefTypeLoc | 类、结构体、联合体、枚举、typedef / using 类型别名；不是完整 C++ 类型/模板索引 |

引用是语法观测，包含 `sizeof` / `noexcept` 和丢弃分支中的已解析名称，也包含全局初始化表达式。声明/定义的名字本身不算引用，但其类型及初始化表达式可产生引用。未解析的模板依赖名称、宏定义/宏名称索引、字符串中的名字、命名空间限定符和所有别名语义不在覆盖保证内。

位置使用宏展开处的行和 UTF-8 字节列。同一编译单元中，目标、位置、类别及所属函数相同的记录合并；宏中的重复同目标展开可能只形成一条。共享头文件按每个成功 TU 保留观测，因此观测数不等于不同源码位置数。失败 TU 的引用全部丢弃，既有每 TU 覆盖和命令指纹可用于追溯实际编译环境。

符号仍以 Clang USR 为基础，内部/无链接符号补充文件路径；内部链接符号及其所属局部符号再加 `@tu=...`，区分共享头文件在不同 TU 中的静态实体。这会改变相关旧符号 ID，不应跨分析器版本仅靠旧 ID 推断问题已修复。

源码告警按规则、位置及去掉 TU 后缀的函数身份去重，保留第一成功 TU 的实际函数 ID 作代表。引用中的多个实体不因此合并；告警也没有被扩展成逐 TU 缺陷证据。如果代表 TU 改变，版本比较可能显示新增/未再检出，仍需结合解析覆盖复核。

## 函数度量

| 字段 | 定义 | 限制 |
|---|---|---|
| max_nesting | 函数体中 if、for、范围 for、while、do、switch、try 的最大语法控制深度 | 单独花括号、逻辑/三元运算符不增加层级；else-if 计嵌套；lambda 体及局部类方法不归外层函数；包含语法上的丢弃分支 |
| fan_in | 成功 TU 调用边中，调用当前函数的不同源符号数 | 仅限已解析静态端点，重复调用点和共享头文件不重复增加同端点计数；自调用计一个端点 |
| fan_out | 当前函数直接调用的不同目标符号数 | 包含可标识显式构造；函数指针、完整虚分派、隐式析构、全局初始化和独立 lambda 调用关系未建模 |

圈复杂度、行数、参数数及最大嵌套来自同一被选中的函数定义；重复定义按最高 CFG 复杂度选择，复杂度相同按清单合并顺序保留。图及扇入扇出是成功 TU 的并集，不是某个单一运行配置的完整调用图。调用收集排除 `sizeof`、`noexcept`、当前不建模的 `typeid`，并排除可确定的 `if constexpr` 丢弃分支；普通运行时分支不会进行路径可行性证明。

新增度量缺失时为 `-1`，Qt/HTML 显示“未知”；CLI/JSON/查询保留 `-1`。查询“零引用/零扇出”时应同时检查索引版本、解析状态和覆盖范围。

## 存储、缓存与报告

SQLite schema 7 增加 `symbol_reference`、`analysis.reference_index` 和三个函数度量列。引用主键按扫描、目标和位置/TU 建索引，外键连接目标符号及来源 TU；随扫描事务提交。Core 当前仍加载完整快照后在内存查询，没有宣称按符号直接分页读取大型数据库。

schema 1—6 只读打开不迁移，写入时附加迁移。历史快照 `reference_index` 为空、度量为 `-1`；引用 API 和查询会提示重新分析，不能把旧索引缺失当成零结果。成功 TU 产生的新索引标记为 `resolved_ast_v1`，部分失败由原分析状态说明。

TU 缓存格式升级为 2，保存引用及嵌套度量；扇入扇出在所有 TU 合并后重新计算。分析器指纹随源码更新，使旧缓存自然失效。HTML/JSON 报告增加引用、来源 TU 和新度量，JSON 同时输出调用/include 边；仍为只读快照导出，不重新读取历史源码推测关系。
