# Juliet 清洗、图语义特征与分类对照

## 修正范围

本轮固定复用首批 120 个用例对。生成代码经 v2 清洗后重新编译、构图与校验，去重后仍为 239 个函数；训练/验证/测试的样本 ID 集合与旧批次逐项相同，数量仍为 145/40/54。新产物位于 `artifacts/layer2/juliet-correction-20260908`。

### 命名清洗

旧检查只发现 good/bad 前缀，漏过 `dataGoodBuffer`、`dataBadBuffer`。现按标识符任意位置检查；在已识别的受控 C 局部变量声明上使用唯一中性名称，一致替换其引用。改名保持作用域、遮蔽关系、数值、运算符和行数，不替换字符串、成员名或外部函数。遇到无法安全处理的答案线索即拒绝该用例。改名映射仅保存于 `provenance.jsonl`，不进入模型输入。

同批 18 个函数进行了改名，生成函数的答案线索复查为 0。240 份原始文件与生成文件的哈希均验证通过。这是对已知线索的检查，不能证明所有合成模板特征都已消除。

### 语义特征版本

原生分析器现在在整数和字符常量节点保留十进制值；原有运算符、类型和函数内稳定变量 ID 继续输出。`semantic-v2` 在原有六维结构特征上增加常量存在标志、带符号对数常量值、数组第一维容量对数和函数内绑定 ID；节点词表额外区分运算符。绑定 ID 来自 Clang 声明引用关系，与变量拼写及文件路径无关。

旧特征下，11 组（23 个函数）的正负样例具有完全相同的 GNN 输入。新版在该批次上的冲突数降为 0。这个检查只排除逐张量完全相同的输入，不证明网络一定能正确分类，也不涵盖浮点常量、完整数组形状、指针别名或跨过程语义。

`train-model --feature-version semantic-v2` 是新的 CLI 默认配置；`legacy-v1` 可用于结构特征对照。新检查点记录特征版本与特征名称；旧检查点缺少版本字段时沿用六维特征。语义模式遇到没有整数常量值的旧图会明确要求重新构图。

### 分类与定位监督

训练中没有任何正例行监督时，定位损失自动为 0。也可使用 `--localization-weight 0` 显式运行纯分类。此类检查点不输出未训练的行排名，在线告警仅显示函数入口。每轮分别记录分类、定位及总损失，避免将负例行定位损失下降误认为分类改善。

## 对照方案与扩容门槛

训练前写入 `plan.json`，固定 40 轮、学习率 0.003、阈值 0.5、来源组划分及数据哈希。全部使用清洗后的同一份数据和纯分类损失：

- GNN：`legacy-v1` 与 `semantic-v2`，分别使用 42/43/44 三个种子；比较图特征。
- 融合模型：`semantic-v2`、512 tokens，使用 42/43/44 三个种子；验证修正组合。
- 序列模型：256 与 512 tokens，均使用种子 42；仅作为长度影响的初步对照。

共 11 次训练。每次以验证集分类 BCE 选轮次；分类阈值固定。旧批次的 3–5 轮冒烟结果只作故障背景，不与本轮做严格效果归因。

预登记的扩容门槛为：融合模型三个种子的验证集平均平衡准确率至少 0.60，且至少两个种子同时预测正负类；同时须通过清洗、同批切分、特征冲突、编译构图、检查点重载和回归检查。该门槛用于决定工程投入，不是显著性检验或正式研究指标。

当前测试集已参与前一轮问题诊断，本轮结果应视为开发对照，不能作为全新独立留出集。未来扩容须另外保留未参与开发的来源组。训练、验证和测试的类别覆盖不同，跨类别泛化还需单独评估。

## 本轮验收结论

11 次训练全部完成，每次 40 轮。下表除序列模型外均为三个种子的均值；序列模型仅种子 42。验证与测试中正负样例均衡，因此表中的平衡准确率也等于普通准确率。

| 配置 | 验证平衡准确率 | 测试平衡准确率 | 测试 F1 | 测试 ROC-AUC |
|---|---:|---:|---:|---:|
| GNN 原结构特征 | 50.0% | 51.2% | 0.422 | 0.550 |
| GNN semantic-v2 | 56.7% | 67.3% | 0.693 | 0.700 |
| 融合 semantic-v2 / 512 | 50.0% | 63.0% | 0.627 | 0.715 |
| 序列 / 256 / seed 42 | 57.5% | 70.4% | 0.742 | 0.731 |
| 序列 / 512 / seed 42 | 50.0% | 61.1% | 0.512 | 0.723 |

新 GNN 的训练集平均平衡准确率为 73.1%，旧结构特征为 52.9%；这支持语义特征补充的方向，但泛化仍有明显差距。融合的验证平衡准确率逐种子为 42.5%、47.5%、60.0%，均能预测出正负类，平均为 50.0%，未达到预登记的 60% 门槛。因此本轮决定暂缓扩容；没有启动 300–500 用例对的新批次。

512 tokens 消除了本批全部截断（66 → 0），但本次单种子序列对照没有显示分类收益，不能推断输入越长就一定更好。融合也未在验证集超过纯图基线。后续优先检查序列池化、图特征缩放和融合头的泛化；按来源组分析验证误差，并用验证集预登记少量控制变量实验。现有测试指标作为开发诊断保留，不据其挑选种子或模型。

技术验收已通过：120 项完整原生/ML 回归成功，后续两项分类定位相关定向检查成功；旧检查点兼容。实际原生在线扫描覆盖 240 个函数，产生 144 条模型告警，概率与新版 GNN 离线预测逐项一致，源码未变。融合检查点的 54 个测试预测重载一致。告警数量只验证接口，不代表检测精度。机器可读结论见该批次 `acceptance.json`。

## 复现命令

在项目根目录设置 `PYTHONPATH=src`，使用 `.venv-ml/Scripts/python.exe`，将下方输出路径换成尚不存在的新目录。先构建原生分析器，再分阶段运行：

```powershell
cmake --build native/clang_tool/build --parallel 2
$env:PYTHONPATH = "$PWD\src"
.\.venv-ml\Scripts\python.exe scripts/accept_juliet_correction.py prepare --output artifacts/layer2/juliet-correction-new
.\.venv-ml\Scripts\python.exe scripts/accept_juliet_correction.py audit --output artifacts/layer2/juliet-correction-new
.\.venv-ml\Scripts\python.exe scripts/accept_juliet_correction.py plan --output artifacts/layer2/juliet-correction-new
.\.venv-ml\Scripts\python.exe scripts/accept_juliet_correction.py train --output artifacts/layer2/juliet-correction-new
.\.venv-ml\Scripts\python.exe scripts/accept_juliet_correction.py summarize --output artifacts/layer2/juliet-correction-new
```

`--baseline` 指向原批次，`--archive` 指向已核验归档，`--compiler` / `--native` / `--encoder` 可覆盖本机默认路径。中断后可用 `train --run <计划中的名称>` 单独补齐尚未生成的模型；已存在的非空检查点目录会被拒绝覆盖。

`preparation.json` 记录编译构图与相同样本/划分检查；`feature-audit.json` 保存清洗和图特征冲突详情；`comparison.json` 从预测重新核对指标，并记录扩容门槛判断。
